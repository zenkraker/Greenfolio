# M0 — Foundations, dev-first (Sprint 1, Wk 1–2)

Revises the original M0 in the project brief (§5) toward a dev-first sequence: get a
fully working local stack and CI green before spending money on infrastructure that
doesn't change how the code gets written.

## Scope

- **Repo + devcontainer**: `.devcontainer/` (Dockerfile + `devcontainer.json`) and a root
  `docker-compose.dev.yml` — app, Postgres 16, Umami, with Hangfire running in-process
  inside the app (there's no standalone Hangfire container image; its dashboard and
  background job server both run in the ASP.NET Core process against Postgres storage).
  Verified on DevPod/Coder and plain VS Code.
- **Initial EF Core migration** covering the full §4.1 schema, including the
  `sources` / licence-tracking fields from day one.
- **Taxonomy v1 + EuroSciVoc crosswalk skeleton** seeded (draft fields/topics, pending
  PO review; crosswalk reuses the field mapping validated in the Week 1 data spike).
- **CI**: a locally-run GitLab pipeline (`.gitlab-ci.yml`, executed via
  [`gitlab-ci-local`](https://github.com/firecow/gitlab-ci-local)) — **not** GitHub
  Actions. Stages: build, test (Testcontainers against Postgres), image publish to a
  registry. `gitlab-ci-local` was chosen over standing up a full self-hosted GitLab CE
  instance: it runs `.gitlab-ci.yml` pipelines directly against the Docker daemon with no
  server to install or maintain, which fits a dev-first, one-command-on-a-clean-machine
  milestone. A full GitLab CE + Runner pair is real infrastructure (4GB+ RAM, its own
  Postgres/Redis, ongoing upkeep) that buys nothing at this stage — revisit only if the
  team specifically needs GitLab's web UI, merge-request integration, or pipeline
  history during M0/M1.
- **Dev-DB backup/restore script** (`pg_dump`/`pg_restore`), proven by an actual
  backup → restore round-trip against the dev stack, not just "the script runs."
- **Legal pages** (Impressum, Privacy Policy EN) drafted as content only — shipping
  (wiring into rendered pages) deferred to first release, per brief §3.2 / §4.2.
- **No VPS purchased yet.**
- **Domain purchased + DNS parked** — blocks nothing at this stage, enables Search
  Console verification later. This is a PO/Ops action (registrar purchase, payment),
  not something engineering executes; tracked as an open action item, not done here.

## Exit criteria

1. `docker compose -f docker-compose.dev.yml up` (or `devpod up` / a Coder workspace) →
   running app + seeded dev DB, in one command, on a clean machine.
2. CI green — `gitlab-ci-local` runs the full pipeline (build, test, image publish)
   successfully.
3. Migration is reversible — applying and rolling back the initial EF Core migration
   both succeed cleanly.
4. Taxonomy reviewed — v1 fields/topics are seeded and ready for PO sign-off (open
   decision #3 in brief §8).

## What this does not include

VPS provisioning, Caddy/TLS, the public site, actual CORDIS/OpenAlex/ROR ingestion
(that's M1), and shipping the legal pages into rendered routes (first release). Domain
purchase is a pending manual action, tracked here so it isn't lost, not a blocker for
anything in this milestone.
